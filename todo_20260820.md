## Priority 2 — Identity resolution (the hardest, highest-value unsolved piece)

- [x] *(Partial)* Real cross-source identity pairs now resolving correctly for two concrete cases

## Priority 4 — Storage architecture fixes

- [ ] **Snapshot + compaction model.** Introduce periodic consolidation of the event chain into a snapshot: final state + evidence pointers to latest source, with full history kept separately in a colder, more compressed archive. Separates "needed for audit" from "needed for fast queries."
- [ ] **Materialized views alongside EAV.** Keep EAV (RFC 0016) for genuinely dynamic/heterogeneous facts, but add typed, denormalized indexes for frequently queried structural patterns (e.g., dependency lookups, already partially done) to avoid repeated EAV self-joins.
- [ ] **Explicit v2 → v3 deprecation timeline.** Publish when SQLite (v2) stops being the default and v3 (fact-segment engine) becomes standard, plus a single migration tool with dry-run/verify (partially exists via `ekos ledger migrate --v3`).
- [ ] **Write-barrier / concurrency spec.** Formalize the single-writer model (`memory-keeper`-only writes) with versioned snapshots for readers (MVCC-style) so concurrent MCP reads during a write are guaranteed consistent.
- [ ] **Recovery path for corrupted segments.** Add a write-ahead log before final immutable segment writes, plus a repair tool that reconstructs from WAL + last valid snapshot — currently the only recovery option is a full rollback of the entire v3 migration.
- [ ] **Retention/pruning policy.** Define what happens to Events for facts that become permanently irrelevant (deprecated APIs, deleted code) — currently the ledger has no upper bound and no archival strategy beyond compaction of existing data.
