Testing EKOS on a Postgres project

Tnhn asked me to test EKOS on a Postgres project, with this business problem:

“When a payment fails or status changes, I can't trace where it comes from. I have to search 3 places: Postgres DB, backend code, and PDF invoices. It's hard to know which code updates payment status.”

What was wanted from EKOS: not just a chat answer, but a final document that shows

  1. Data lineage
  2. Code evidence — which file and function updates payment_status
  3. Links to the actual code lines and DB columns as proof

I could not apply it to that project, so I took LedgerSMB — a real Perl 5 / PostgreSQL accounting ERP.

I added a PostgreSQL adaptor. To get a clean result I deleted the doc/ folder and README.md, so nothing in the answer could come from documentation somebody had already written, and ran EKOS on the project.

It turned out there is no payment_status column at all. Status lives in a workflow engine, reached through the general ledger, and exactly one function in the codebase writes it.
