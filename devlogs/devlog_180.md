## PR — RFC 0138 Phase 4: hard-fail on mock, per-provider key-env default

### Problem / motivation

`ekos eval run` opens a real `LlmProvider` via `build_llm_provider` — the same selection logic
`recover`/`commit` use, where degrading to a canned-response `MockLlmProvider` on a missing API
key is a reasonable, deliberate fallback (structural analysis without LLM enrichment is a
legitimate mode there). For `ekos eval`, the same fallback is silent data corruption: the harness
would still run all 101 scenarios, grade the mock's fixed response against every rubric, and print
(and optionally save) a fully-formed `EKOS EVALUATION` report with a real-looking `PASS`/`FAIL`
verdict — indistinguishable, without reading the transcripts, from a report generated by an actual
model.

### What was built

| Item | Where | What |
|---|---|---|
| Hard-fail on mock | `crates/cli/src/commands/eval.rs` | `check_not_mock` bails with an actionable message if `build_llm_provider` returned the stub |
| Per-provider key-env default | `crates/cli/src/commands/recover.rs` | `default_key_env`/`resolved_key_env` replace one shared literal |
| Detectable mock identity | `crates/recovery/src/llm.rs` | `MockLlmProvider`'s fixed model name promoted to a `pub const MOCK_MODEL_NAME` |
| Docs | `README.md`, `docs/generated/ekos-self-documentation.html`, `TODO.md` | Local-model-needs-a-powerful-server guidance, reference-baseline recommendation |

### Implementation details worth remembering

**Detecting "this is the mock" needed no new plumbing.** `MockLlmProvider::model_name()` already
returns a fixed, non-configurable `"mock-v1"` string — the simplest possible signal, reachable
through the existing `&dyn LlmProvider` trait object with no `Any`/downcasting. Promoted it to a
`pub const MOCK_MODEL_NAME` (in `llm.rs`, re-exported from the crate root) so `eval.rs`'s check
compares against a named constant instead of a string literal that could silently drift out of
sync with the one inside `MockLlmProvider::new`.

**Confirming there's no legitimate way to reach the mock deliberately mattered.** `EvalRunOpts`'s
`--agent` only accepts `claude`/`anthropic`/`ollama`/`openai` (`run`'s own `match` rejects anything
else with `anyhow::bail!`) — there is no `--agent mock`. That means the hard-fail can never
misfire against an intentional choice; reaching `MOCK_MODEL_NAME` at the point `check_not_mock`
runs can only mean the API-key fallback fired.

**The real bug found along the way: `build_llm_provider`'s `key_env` was computed once, before
branching on provider, and reused unchanged for both the `openai` and default-Anthropic paths.**

```rust
// before
let key_env = config.llm.api_key_env.as_deref().unwrap_or("ANTHROPIC_API_KEY");
if config.llm.provider.as_deref() == Some("openai") {
    return match OpenAiProvider::from_env_var(key_env) { .. };  // checks ANTHROPIC_API_KEY!
}
```

A workspace with `[llm] provider = "openai"` and a real `OPENAI_API_KEY` set, but no explicit
`api-key-env` override, silently degraded to the mock — `OpenAiProvider::from_env_var` was asked
to check `ANTHROPIC_API_KEY`, which was never set. The warning logged even said the wrong variable
was missing. This wasn't a hypothetical found by inspection alone: it's exactly the shape of bug
the hard-fail this session was building exists to surface, so building the hard-fail's error
message (which needed to *name* the actual key to set) forced tracing `key_env`'s real value and
finding the mismatch. Fixed with a small `default_key_env(provider) -> &'static str` match, and a
`resolved_key_env(config) -> &str` that applies `[llm] api-key-env` as an override over it —
exposed `pub` so `eval.rs`'s error message and `build_llm_provider` itself share one source of
truth rather than two independent guesses at "what env var does this provider need".

### Decisions (alternatives considered, why this choice)

- **Extracted `check_not_mock` as a standalone, synchronous, pure-ish function** (`&dyn
  LlmProvider` in, `Result<()>` out) rather than inlining the check into `run()`. `run()` itself is
  hard to unit test directly (opens a real store, needs dataset files on disk, is `async`); the
  extracted function needed neither and could be tested directly against both a real
  `MockLlmProvider` (must fail) and a `MockLlmProvider` struct literal with a different `model`
  field (must pass, standing in for "any real provider" without needing actual credentials).
- **Verified the key-env fix and the mock-detection fix each with dedicated tests**, not just the
  end-to-end hard-fail path — `resolved_key_env`'s three cases (openai default, anthropic default,
  explicit override always wins) are pure and need no environment mutation, avoiding the
  process-global `env::set_var` race that would otherwise threaten `cargo test`'s default
  parallelism, the same reason the pre-existing `non_ollama_provider_falls_back_to_existing_chain`
  test already tolerates either ambient env state rather than asserting one.
- **Documented the P95 figure already measured and printed in the README's own eval-harness
  section (49.4s), not a separately-quoted number from an old TODO note (36s)** — the two numbers
  come from different runs and would read as inconsistent sitting next to each other in the same
  document; the number already surfaced in a real, reproduced report table in this same file was
  the more defensible one to repeat.

## Knowledge Captured

- **A "reasonable default" in one caller can be a silent data-integrity bug in another.**
  `build_llm_provider`'s Mock fallback is correct, deliberate, documented behavior for
  `recover`/`commit`. The exact same function, called from `ekos eval`, turns that same fallback
  into "the report says PASS/FAIL for a model that never ran." The fix wasn't to change
  `build_llm_provider`'s behavior — it was to add a caller-specific check for the one consumer
  where silent degradation is unacceptable, without touching the shared function's contract for
  every other caller.
- **A single shared default computed before a branch is a common way to reintroduce the exact bug
  a later branch was added to avoid.** The `openai` branch was added "mirroring the Anthropic path
  exactly" (per its own comment) but inherited a piece of state — `key_env` — that was never
  re-derived per branch. Any time a `match`/`if` grows a new arm, check whether every value
  computed *before* the branch still means the same thing inside the new one.
- **Tracing a value all the way through to build an error message is a legitimate bug-finding
  technique**, not just a code-quality nicety. This bug wasn't found by reading `build_llm_provider`
  looking for bugs — it was found by trying to write an honest error message ("tell the user which
  key to set") and discovering the value being surfaced didn't match the branch it was reached
  from.
